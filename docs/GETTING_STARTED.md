# 看懂这个项目的 YOLO 训练过程

这个项目要解决的问题很直接：给模型一张工地图片，让它找出戴安全帽和没戴安全帽的头部，并画出位置。

从代码上看，整个过程就是：

```text
准备带标注的图片 → 训练模型 → 选出表现最好的权重 → 测试效果 → 用来检测新图片
```

## 1. 准备数据：告诉模型正确答案

每张训练图片都配有标注，记录目标的位置，以及它属于“戴帽”还是“未戴帽”。模型训练时，要拿自己的预测和这些标注比较。

项目清理后保留了 7026 张图片，分成三份：

| 数据 | 数量 | 用来做什么 |
| --- | ---: | --- |
| 训练集 | 4916 张 | 让模型学习 |
| 验证集 | 1406 张 | 检查学习效果、选择模型和阈值 |
| 测试集 | 704 张 | 报告最终效果 |

划分前还检查了相似图片，尽量把同一场景的相似样本放进同一份数据，减少模型“见过类似考题”带来的影响。这不能保证识别出所有相似场景。

对应代码：[prepare_dataset.py](../scripts/prepare_dataset.py)。

## 2. 训练模型：预测、比较、调整，反复执行

项目使用已经预训练过的 YOLO26n，再用安全帽数据继续训练。这个过程通常叫“微调”。

训练时，框架反复执行三步：

1. 给模型一批图片，让它预测目标的类别和位置。
2. 将预测和标注比较，计算误差，也就是 loss。
3. 根据误差调整模型参数，再处理下一批图片。

训练集完整处理一遍叫一个 epoch，也就是一轮。核心调用如下，参数更新等步骤由 Ultralytics 框架完成：

```python
from ultralytics import YOLO

model = YOLO("weights/yolo26n.pt")
model.train(
    data="datasets/hard-hat-workers/yolo/data.yaml",
    epochs=100,   # 最多训练 100 轮
    batch=8,      # 每批输入 8 张图片
    imgsz=640,    # 输入尺度配置
    patience=20,  # 验证表现连续 20 轮未改进就停止
    seed=42,
)
```

项目的实际入口还负责选择设备、保存结果和记录训练状态，见 [train_helmet.py](../scripts/train_helmet.py)。

## 3. 选模型：看验证集表现

每轮训练结束，框架都会用验证集检查模型。验证集不参与参数更新，可以帮助判断模型面对训练集以外的图片时表现如何。

本次训练在第 60 轮取得最好的验证集综合检测指标（mAP50–95），保存为 `best.pt`。之后连续 20 轮没有超过它，于是在第 80 轮结束训练。

因此，最后拿来使用的是第 60 轮选出的权重。即使后面训练图片上的误差继续下降，验证效果没有改善，也不会换掉这份最佳权重。

每轮记录可以直接看 [results.csv](../runs/helmet/yolo26n_100e_b8_20261015_145934/results.csv)。

## 4. 测试效果：看误报和漏报

选好模型后，用测试集报告效果。程序还需要决定多有把握才显示一个预测，这由“置信度阈值”控制。本项目在验证集上选定 **0.40**，随后用这个固定值统计测试结果。

对“未戴帽”这一类，本次测试结果可以这样理解：

- 模型报出的未戴帽目标中，约 **92.5%** 报对了，这叫查准率。
- 标注中的未戴帽目标中，约 **89.2%** 被模型找到了，这叫召回率。

两者一起看，才能同时了解误报和漏报。这些结果来自当前测试集，换到另一个工地仍需要验证。

标准检测指标由 [evaluate_helmet.py](../scripts/evaluate_helmet.py)计算；阈值选择和上面的固定阈值统计由 [validate_monitor.py](../scripts/validate_monitor.py)完成。

## 5. 用模型：加载权重，检测新画面

训练产出的 `best.pt` 保存了学到的模型参数。应用程序加载它，就可以检测新的图片或逐帧处理视频，无需每次重新训练。

[monitor_helmet.py](../scripts/monitor_helmet.py)负责加载模型、预测、绘框和保存结果。权重路径与阈值保存在 [monitor.json](../config/monitor.json) 中。画面中绿框代表戴帽，红框代表未戴帽；人数只统计当前帧，不做跨帧人员去重。

阅读代码可以按“数据准备 → 训练入口 → 测试评价 → 应用推理”的顺序。先看清每一步的输入和输出，再根据兴趣进入框架实现。
